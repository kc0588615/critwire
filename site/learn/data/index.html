Files

Each file is a plain download; Parquet files can also be queried in place, for example from DuckDB. The labs also read critwire's species and countries files under /v1/. The lab files sit outside /v1/ because they change as the course does: check manifest.json, which lists every file's columns, rows, size, sha256 and sources, and the /v1/ files' sha256 the labs were tested with.

Total: {{totalBytes}}. Shapes are GeoParquet 1.0.0: the outline is in a geom column as WKB, in longitude and latitude (WGS 84). Some outlines are invalid on purpose, for the lab on fixing geometry.

Reading the CSV files: Namibia's country code is NA, which some tools read as a missing value. An empty cell is the missing value. In pandas, pass keep_default_na=False, na_values=[""] to read_csv; in R, pass na.strings = "" to read.csv. DuckDB and the Parquet files keep it as the text NA.

PostGIS

learn_curriculum.sql builds every lab table in the schema learn_curriculum with nothing but psql and the PostGIS extension:

psql -X -v ON_ERROR_STOP=1 -d your_database -f learn_curriculum.sql

It runs as one transaction and checks its own row counts before it commits. Loading it again replaces the whole schema, including any tables you added to it; a failed load leaves the previous schema as it was. It refuses to run if anything outside the schema depends on it, such as one of your views. A database used only for the labs avoids both problems.

The GBIF sample

The occurrence files hold {{records}} records of critwire's species from {{datasetCount}} datasets shared through GBIF. They come from one GBIF download, so anyone can fetch the same records again: {{downloadDoi}}.

Each record is open: its license, or its dataset's when that is stricter, is CC0 1.0 or CC BY 4.0, and the license column says which. Each species has at most 2,000 records, chosen by the lowest md5 of the GBIF id, so any database picks the same ones. These are records of where people saw or collected an animal, not maps of where it lives.
