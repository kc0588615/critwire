The browser

Nothing to install. A current desktop browser opens a module page, and its SQL runs there in DuckDB, which critwire serves itself: no request leaves critwire.com except for the animals' photos. Each visit builds the database once, from four published files: /v1/species.parquet, /v1/countries.parquet, /learn/data/datasets.csv and /learn/data/occurrences.parquet. Every learner starts from the same tables, and a reload starts fresh. A result keeps at most 10,000 rows. Stop ends a long query, and Reset database rebuilds the tables, both by restarting the database. The browser's tables lists every column.

This query counts the rows of every table, and of the view species_taxonomy. Run it: the same numbers mean your browser built the same database as everyone else's.

{{block:setup-counts}}

Coordinates as numbers. The browser has no spatial functions (the ST_ family): DuckDB's spatial extension is large, so critwire doesn't serve it. The foundations still use longitude and latitude as plain numbers: a bounding box is longitude BETWEEN … AND latitude BETWEEN …, floor(longitude / 10) and floor(latitude / 10) put records into 10° boxes, and the haversine formula gives the distance along the Earth's surface. Anything with shapes (outlines, projections, spatial joins and indexes) runs in PostGIS.

PostgreSQL with PostGIS, on your computer

The database architecture and GIS modules run in PostgreSQL, a database server, with PostGIS, its spatial extension, on your own computer. The labs are tested on PostgreSQL 16 with PostGIS 3.4. On Windows, the simplest way to get exactly that pair is Docker.

With Docker Desktop (recommended)

Install Docker Desktop with its WSL 2 backend. Then, in PowerShell:

# PostgreSQL 16 with PostGIS 3.4, the tested pair, reachable only from this computer.
docker run -d --name learn-pg -e POSTGRES_PASSWORD=choose-a-password -p 127.0.0.1:5432:5432 -v learn-pg:/var/lib/postgresql/data postgis/postgis:16-3.4
docker exec learn-pg psql -U postgres -c "CREATE DATABASE learn"
docker exec learn-pg psql -U postgres -d learn -c "CREATE EXTENSION postgis" -c "CREATE EXTENSION postgis_raster"
# The lab file: every lab table, in one transaction.
curl.exe -fLo learn_curriculum.sql https://critwire.com/learn/data/postgis/learn_curriculum.sql
docker cp learn_curriculum.sql learn-pg:/tmp/
docker exec learn-pg psql -X -U postgres -d learn -v ON_ERROR_STOP=1 -f /tmp/learn_curriculum.sql

The image postgis/postgis:16-3.4 is the tested pair, but it hasn't been rebuilt since October 2024, so its PostgreSQL minor release is old. That is fine for a lab only your own computer can reach (the 127.0.0.1: in -p), and for nothing else. The tags 16-3.5 and 16-3.6 run the labs too, but their newer GEOS (the geometry library under PostGIS) can change the last digits of some measurements, so a result may differ slightly from the one printed. PowerShell has no < redirection, so the file is copied into the container and read with -f. On Linux or macOS the same commands work in a terminal, with curl for curl.exe. The image is built for x86-64 only.

Without Docker

Install PostgreSQL 16 with the EDB installer, then run Stack Builder → Spatial Extensions → the PostGIS 3.4 or 3.5 bundle for PostgreSQL 16. If port 5432 is taken (by another PostgreSQL, or by ArcGIS), choose 5433 in the installer and add -p 5433 to each psql line below.

$psql = "C:\Program Files\PostgreSQL\16\bin\psql.exe"
& $psql -U postgres -c "CREATE DATABASE learn"
& $psql -U postgres -d learn -c "CREATE EXTENSION postgis" -c "CREATE EXTENSION postgis_raster"
curl.exe -fLo learn_curriculum.sql https://critwire.com/learn/data/postgis/learn_curriculum.sql
& $psql -X -U postgres -d learn -v ON_ERROR_STOP=1 -f learn_curriculum.sql

psql on Windows talks to the server in the console's code page unless told otherwise. The lab file sets its own encoding to UTF-8, so names like "Côte d'Ivoire" arrive intact either way.

Loading, and loading again

learn_curriculum.sql (its size is on the lab data page) builds the schema learn_curriculum in one transaction: it drops the schema, creates it again, loads every table, adds the keys and indexes, and checks every table's row count before it commits. A failed load changes nothing. A second load replaces the schema, including any table you made in it, so keep your own work in another schema. Another schema keeps your tables, but not what depends on the lab: a view, foreign key, trigger or policy of yours that reads learn_curriculum would be dropped with it. The lab file refuses that reload instead, naming each such object, and changes nothing; move or drop them, then load again. The lab schema lists every table and column.

Connection settings

Any lab file you run with psql finds the database through libpq's standard environment variables, so the same file runs on your computer and on critwire's test server. In PowerShell, for one session:

$env:PGHOST = "localhost"; $env:PGPORT = "5432"; $env:PGUSER = "postgres"; $env:PGDATABASE = "learn"
# The password goes in %APPDATA%\postgresql\pgpass.conf, one line: localhost:5432:learn:postgres:choose-a-password

Privileges

The postgres user is a superuser and can do everything the labs do. As another user, you need:

  • CONNECT, CREATE and TEMPORARY on the database, to connect, to load the lab and to make temporary tables (the database's owner has them; otherwise, as the superuser: GRANT CONNECT, CREATE, TEMPORARY ON DATABASE learn TO you;), and ownership of learn_curriculum once it exists;
  • CREATEROLE, for the labs that create roles: as the superuser, once, ALTER ROLE you CREATEROLE;, and on PostgreSQL 16 and later also ALTER ROLE you SET createrole_self_grant = 'set, inherit';, so you can act as the roles you create (SET ROLE) and drop what they hold (the roles module explains);
  • nothing more for the raster labs: their raster clips are stored in the database itself.

Give the labs a database of their own, one you could drop and create again, and keep other work out of it. CREATEROLE applies to the whole server, not one database, so give it to a user you keep for the labs. Every role or schema a lab creates is named learn_… and removed by the same block, so the labs leave nothing in your database besides learn_curriculum.

Python

The spatial statistics and ETL modules run Python scripts that read the same lab database. They run in a virtual environment: a folder holding one Python and exactly the package versions the labs were tested with. uv builds it with the same commands on Windows, Linux and macOS, installs Python 3.12 itself, and installs the versions requirements.txt pins. --no-build makes it stop with an error rather than compile a package that has no prebuilt version for your computer.

Windows (PowerShell)

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/0.13.5/install.ps1 | iex"
mkdir $HOME\learn; cd $HOME\learn
curl.exe -fLo requirements.txt https://critwire.com/learn/labs/requirements.txt
uv python install 3.12
uv venv --python 3.12
uv pip sync --no-build requirements.txt
.venv\Scripts\python -c "import geopandas, esda; print(geopandas.__version__, esda.__version__)"

Linux and macOS

curl -LsSf https://astral.sh/uv/0.13.5/install.sh | sh
mkdir -p ~/learn && cd ~/learn
curl -fLo requirements.txt https://critwire.com/learn/labs/requirements.txt
uv python install 3.12
uv venv --python 3.12
uv pip sync --no-build requirements.txt
.venv/bin/python -c "import geopandas, esda; print(geopandas.__version__, esda.__version__)"

The last line prints two version numbers. GeoPandas and esda import most of the rest, so if they load, the environment is complete.

The environment

requirements.txt pins 44 packages, each to one version: GeoPandas and Shapely for shapes, pyproj for coordinate systems, psycopg to talk to PostgreSQL, and PySAL's libpysal, esda and pointpats for spatial statistics, with what they need. Every pin has a prebuilt package for Windows on x86-64, Linux on x86-64 and ARM, and macOS 14 or later on Apple silicon. Intel Macs aren't covered: pyproj 3.8.0 has no build for them. uv pip sync installs exactly the file and removes anything else, so run it again whenever you download a newer requirements.txt.

Scripts and notebooks

Each module's lab is one .py file, split into cells by # %% lines, and the same cells as a notebook (.ipynb). Run a file whole (.venv\Scripts\python setup.py on Windows, .venv/bin/python setup.py elsewhere), or cell by cell in VS Code or Jupyter. The first time, the editor asks to add ipykernel, the package that lets it run cells, to the environment. Let it: nothing here depends on it, and the next uv pip sync removes it again.

A lab file finds the database through the same PG* variables as psql (Connection settings, above), with the password in the same pgpass file or in PGPASSWORD. critwire runs every Python lab as an ordinary user with the privileges listed above, not as a superuser.

arcpy notes (ArcGIS Pro)

For anyone with ArcGIS Pro (the Basic license is enough). This is optional: no lab needs it.

  • arcpy, Pro's Python package, lives in Pro's own conda environment, arcgispro-py3. Don't pip-install into it. If you want a lab package there, clone the environment in Pro (Settings → Package Manager → Environment Manager) and add the package to the clone.
  • Keep the uv environment for the labs, and move data between the two as a GeoPackage (the block above). Pro lists a GeoPackage's layers as main.<name>.
  • Pro Basic's Spatial Statistics toolbox covers s4 and s5: Spatial Autocorrelation (Global Moran's I) and Hot Spot Analysis (Getis-Ord Gi*). Pro reports Moran's z-score under the randomization assumption, so compare it with esda's z_rand, not z_norm (s4 prints both).

This block runs s4's global Moran's I in Pro's Python window, on the GeoPackage written above. critwire can't run it (Pro is licensed and Windows-only), so setup.py carries it commented out and the notebook as text.

Power BI Desktop

Power BI Desktop is free and runs on Windows only. It reads the star schema as CSV files under https://critwire.com/learn/data/star/: no gateway, no account, no database connection. To check your setup, make a blank query (Home → Get data → Blank query → Advanced editor) and paste this in. The first time, Power BI asks how to connect to critwire.com: choose Anonymous, and privacy level Public.

{{block:pbi-smoke}}

It should show 251 rows: 250 countries, plus ZZ, the star's "unknown" member for records in no country. Namibia's code NA stays text. Three choices let it refresh anywhere:

  • A fixed base URL, with the file in RelativePath. The Power BI Service can then refresh the published report on a schedule, with anonymous access. A whole URL assembled from text ("https://critwire.com/learn/data/star/" & file) is a dynamic data source, which the Service won't refresh.
  • Encoding = 65001 (UTF-8) and QuoteStyle.Csv: names with accents, and commas inside quotes, are read as written.
  • The culture "en-US" on the type change: critwire's files write 12.5, which a computer set to a comma-decimal locale would otherwise misread.

critwire checks every file a Power BI query names against the star's manifest (header, keys, rows and sha256) on every build. It can't run Power BI itself, which has no Linux version, so the queries, measures and visuals aren't run by critwire.
