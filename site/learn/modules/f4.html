Concept

A query can use another query's result as a table.

  • A subquery is a query in brackets: in FROM it is a table (give it an alias); in WHERE or SELECT it can return one value (a scalar subquery) or a list for IN. A correlated subquery refers to the outer row (WHERE o.country_code = c.code in the exercise of Joins (f3)) and runs, in effect, once per row.
  • A common table expression (CTE), WITH name AS (…), names a subquery before the main query. Several CTEs, separated by commas, read top to bottom like the steps of a recipe, and each may use the ones above it.
  • A window function computes a value for each row from a set of related rows, its window, without collapsing them as GROUP BY does. OVER (PARTITION BY species_id ORDER BY records DESC) says which rows form the window (the same species) and in which order. row_number() numbers the rows 1, 2, 3; rank() gives ties the same number and skips after them (1, 1, 3); dense_rank() doesn't skip (1, 1, 2). An aggregate with OVER (sum(records) OVER (PARTITION BY species_id)) puts the group's total on every row, so a share is one division. With ORDER BY in the window, sum becomes a running total, and lag(x) reads the previous row's value.
  • Window functions run after WHERE, GROUP BY and HAVING, so they can't be filtered in WHERE: compute them in a CTE and filter outside, as in "Already know this?". They can rank aggregates (rank() OVER (ORDER BY count(*) DESC)) in the same query that groups.

Worked example

Which dataset contributed most of each species' records, and what share is that? Three steps, one CTE each: count records per species and dataset; put each species' total and a place on every row; keep place 1 and join the dataset's title.

The top rows are species with a handful of records, or with one source only, so 100 % says little there; read on down. The Jaguar's sample is 97 % one GPS-collar dataset: most of its 2,000 points are positions of collared animals, not 2,000 separate sightings. Bias in records (s1, in preparation) comes back to this. row_number breaks ties by dataset_key so that place 1 is always one row; with rank, a tie would keep both.

Result

Most species' samples lean on one or two datasets, and for the Jaguar one GPS-collar study is almost everything. Ranks show the cap at work: 13 species share rank 1, so rank jumps to 14 and dense_rank to 2; which you want depends on whether "third place" means "two ahead of you" or "the third distinct value". 2021 is the sample's biggest recent year, and the Devil's records fall sharply after 2010.

Dialects

  • PostgreSQL: as here; also FILTER on window aggregates and named windows (WINDOW w AS (…)); a CTE can be MATERIALIZED or NOT MATERIALIZED; WITH RECURSIVE walks trees such as taxa. No QUALIFY.
  • DuckDB (this page's engine): as PostgreSQL, plus QUALIFY place = 1, which filters on a window function without a CTE, and arg_max(dataset_key, records) for "the value with the largest count" in one aggregate.
  • SQL Server: CTEs and window functions as here (the statement before a WITH must end in ;); no QUALIFY; TOP (1) WITH TIES … ORDER BY row_number() OVER (…) or CROSS APPLY (SELECT TOP (3) …) for top-n per group; count is int, so cast before dividing for a share.
