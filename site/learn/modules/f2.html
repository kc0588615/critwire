Concept

An aggregate function turns many rows into one value: count(*) counts rows, count(year) counts the rows where year isn't NULL, count(DISTINCT dataset_key) counts different values, and sum, min, max and avg do what they say; all but count(*) skip NULLs. GROUP BY splits the rows into groups, one per distinct value of its columns (NULL makes a group of its own), and the aggregates then run once per group, so every column you select must be grouped or aggregated.

The clauses now run in this order: FROM, WHERE (filters rows), GROUP BY, HAVING (filters groups, so it can use aggregates), SELECT, ORDER BY. CASE WHEN … THEN … ELSE … END computes a value row by row: use it to put rows into buckets, or inside sum to count only some rows, which turns one grouped query into a small cross-tab.

The table is occurrences, the lab sample of open GBIF records (the lab data page says how it was drawn): one row per record of an animal at a place and, usually, a date. basis_of_record says what kind of evidence it is: a person's observation, a camera trap or GPS collar (MACHINE_OBSERVATION), a museum specimen, a tissue sample.

Result

The oldest record is from 1599, and some records have no year at all: ask min and count(year) before trusting a date column. Human observations dominate, and almost all of them are recent; most records before 1900 are museum specimens. Many species stop at exactly 2,000 records: that is the sample's cap per species, not a fact about the animals, and step 1's top rows are a tie for that reason. Every dataset in datasets contributed at least one record, and only two licenses remain, because the sample keeps only CC0 1.0 and CC BY 4.0 records.

Dialects

  • PostgreSQL: count(*) FILTER (WHERE year < 1900) is the short form of the sum(CASE …) columns; GROUP BY may name an output column or its position, HAVING may not; / between integers drops the fraction (7 / 2 is 3).
  • DuckDB (this page's engine): also has FILTER, plus GROUP BY ALL (group by every column that isn't aggregated) and aliases in WHERE, GROUP BY and HAVING; / between integers gives a fraction (7 / 2 is 3.5) and // drops it.
  • SQL Server: no FILTER: write sum(CASE …) as here; GROUP BY takes neither aliases nor positions; count returns int (count_big for more rows); / between integers drops the fraction.
