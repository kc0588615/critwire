Concept

A query reads tables and returns a new table; it never changes the data. Its clauses run in a fixed order, whatever order you write them in: FROM picks the table, WHERE keeps the rows whose condition is true, SELECT picks and names the columns, ORDER BY sorts, and LIMIT keeps the first rows. A table has no order of its own, so a result without ORDER BY can come back in any order, and "the first five" means nothing without it. Sort on something unique (add id last), so that ties always fall the same way.

NULL is a missing value: not zero, not empty text, but "unknown". Any comparison with an unknown value is itself unknown, neither true nor false, and WHERE keeps only the rows where the condition is true. So = NULL never matches, and NOT LIKE 'CC%' silently drops the rows whose license is NULL, because "is an unknown license not CC?" is unknown too. Test for a missing value with IS NULL or IS NOT NULL; coalesce(x, 'default') replaces one.

Result

Two animals have no photo, and = NULL counts zero of them. The mammals come back A to Z; the second page is rows 6 to 10 of that same order, which is only stable because the sort ends on a unique column. Dialects

  • PostgreSQL: as here. Ascending sorts put NULL last (NULLS FIRST changes that); LIKE is case-sensitive and ILIKE isn't; LIMIT … OFFSET …, or the standard OFFSET … FETCH FIRST n ROWS ONLY.
  • DuckDB (this page's engine): as PostgreSQL for everything in this module: NULL sorts last, LIKE and ILIKE, LIMIT and OFFSET. It adds conveniences such as SELECT * EXCLUDE (photo_url).
  • SQL Server: SELECT TOP (5) …, or ORDER BY … OFFSET 5 ROWS FETCH NEXT 5 ROWS ONLY; NULL sorts first in ascending order and there is no NULLS LAST; LIKE follows the column's collation, usually case-insensitive; = NULL never matches, as here, under the default ANSI_NULLS ON.
