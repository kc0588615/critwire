About

critwire gives every animal one clean record: its common and scientific names, where it sits on the tree of life, the ids other science databases use for it, and the countries where people have shared open records of it. Some records also have a photo with its credit.

Scientists keep information about the same animal in many different databases, and those databases do not always agree. critwire checks the big open ones against each other. When they agree, the answer goes in the record. When they disagree, critwire leaves the value empty until a person has looked at it, so you never get a guess dressed up as a fact.

Everything is a plain file on this website. There is no account, no key and no limit: download a file, open it in a spreadsheet, or read it straight from code. critwire was built for the game Critter Connect, which uses these same files.

The quickest start, in DuckDB:

SELECT * FROM 'https://critwire.com/v1/species.parquet';

The /v1/ in each address is the version. Inside v1 we only add things: fields keep their names and meanings, and an id always means the same animal.

Files

The species files all hold the same {{species}} records, and the countries files the same country rows. Pick the format that suits your tool.

/v1/species.json
All records as one JSON array. Best for web pages and apps.
/v1/species.csv
One row per animal, for spreadsheets. It leaves out sources (see Fields).
/v1/species.parquet
All records with the same nested shape as the JSON, for DuckDB, pandas, polars or R. Tools can read just the parts they need straight from the web.
/v1/species/{id}.json and /v1/species/{slug}.json
One record per file, by its number or by its name in the address. Both files hold the same record.
/v1/attribution.json
Every source, license and photo credit, plus the datasets behind the country lists. The Credits below are made from it.
/v1/countries.json, /v1/countries.csv and /v1/countries.parquet
One row per country code, with the country's name, continent and region, so you can put a name to the codes in range.countriesWithOpenRecords. See Countries.

Files are served with open CORS and byte ranges, so a web page on any site can fetch them.

The data the critwire Learn labs read, an open GBIF occurrence sample, map shapes and a PostGIS loader, is at /learn/data/. It sits outside /v1/ because it changes as the course does.

Ask questions with DuckDB

Which animals have open records in Brazil?

SELECT id, commonName, scientificName
FROM 'https://critwire.com/v1/species.parquet'
WHERE list_contains("range".countriesWithOpenRecords, 'BR')
ORDER BY commonName;

How many animals are in each class, from the CSV?

SELECT taxonomy_class, count(*) AS animals
FROM 'https://critwire.com/v1/species.csv'
GROUP BY taxonomy_class
ORDER BY animals DESC;

How many animals have open records on each continent, joining the countries file:

WITH recorded AS (
  SELECT id, unnest("range".countriesWithOpenRecords) AS code
  FROM 'https://critwire.com/v1/species.parquet'
)
SELECT c.continent, count(DISTINCT r.id) AS animals
FROM recorded AS r
JOIN 'https://critwire.com/v1/countries.parquet' AS c USING (code)
GROUP BY c.continent
ORDER BY animals DESC;

One animal from the JSON, with the ids other databases use:

SELECT commonName, ids.gbif, ids.col, ids.wikidata
FROM read_json('https://critwire.com/v1/species.json')
WHERE slug = 'jaguar';

Fields

Each record has these fields, in this order. A field that is null (an empty cell in the CSV) means critwire does not know the value yet, or the sources disagree and a person has not settled it. critwire never fills a gap with a guess.

id
critwire's number for the animal. It never changes and is never given to another animal.
slug
A short, readable name for web addresses, like jaguar.
scientificName
The two-part Latin name scientists use, like Panthera onca.
commonName
The everyday English name.
taxonomy
Where the animal sits on the tree of life. It comes from the Catalogue of Life when critwire is sure both name the same animal.
taxonomy.class
The class, like Mammalia (mammals) or Reptilia (reptiles).
taxonomy.order
The order, like Carnivora.
taxonomy.family
The family, like Felidae (cats).
taxonomy.genus
The genus, the first part of the scientific name.
ids
The animal's id in other databases, so you can join critwire with them. null means the match is not settled.
ids.iucn
The IUCN Red List species id. critwire keeps only this number, no Red List data (see Licenses).
ids.gbif
The GBIF Backbone Taxonomy key, for occurrence records on GBIF.
ids.col
The Catalogue of Life id.
ids.wikidata
The Wikidata item, like Q35694.
ids.inaturalist
The iNaturalist taxon id.
ids.ncbi
The NCBI Taxonomy id, used for DNA data.
range
Where the animal has been recorded.
range.countriesWithOpenRecords

Two-letter country codes (ISO 3166-1, like BR for Brazil), sorted. This is not the animal's native range. It lists the countries where GBIF holds open records of it: sightings and museum specimens shared under the CC0 or CC BY licenses. Records in zoos, fossils and records with location problems are left out.

A country with a single record far outside the animal's main region is usually a pet, a zoo animal or a mistake, so it is left out until a person checks it. The list is never empty: when there is no country, it is null, and range.status tells you why.

range.status

Always present. One of:

  • ok: at least one country is listed ({{statusOk}} animals).
  • no-open-records: critwire knows which GBIF animal this is, but no country is left after the open-license and quality checks, so the countries are null ({{statusNoOpenRecords}}).
  • identity-unsettled: critwire could not confirm which GBIF animal this is, so it counted nothing and the countries are null ({{statusIdentityUnsettled}}).
photo
A photo from Wikimedia Commons, or null. Show its credit and license wherever you show the photo.
photo.url
The image file.
photo.credit
Who took or owns the photo.
photo.license
The photo's license, like CC BY 2.0.
photo.page
The photo's page on Wikimedia Commons, with its full details.
sources
A list saying where each value came from: one entry per source. It is in the JSON and Parquet files, not the CSV. In Parquet, a key an entry leaves out is null.
sources[].source
The source's name, like Catalogue of Life.
sources[].fields
The fields this source filled in.
sources[].license
The license of what came from this source.
sources[].retrieved
The date critwire fetched it (YYYY-MM-DD).
sources[].url
The exact address critwire asked, so you can check the answer yourself.
sources[].doi
The source's DOI, a permanent link for citing it.
sources[].checklistKey
For GBIF: the checklist the id belongs to.
sources[].release
For the Catalogue of Life: the release critwire used.
sources[].release.key
The release's dataset key on ChecklistBank.
sources[].release.alias
Its short name, like COL26.10.
sources[].release.version
Its version.
sources[].release.issued
The date it came out.
replacedBy
Usually null. If critwire ever retires a record (say, two turn out to be the same animal), this lists the ids that replace it. Retired ids are never reused.

CSV column names

The CSV flattens each record: a column is the field's path in snake_case, with dots turned into underscores. So taxonomy.class becomes taxonomy_class and range.countriesWithOpenRecords becomes range_countries_with_open_records. Lists (countries and replaced_by) are joined with ;, and null is an empty cell. The file is UTF-8.

Countries

The countries files turn a two-letter code into a place: one row per code, sorted by code. They cover every code the species files use, and every code GBIF uses, so a code that shows up later still has a row. They hold names only, no maps or borders.

Every column is text and never empty, in this order:

code
The two-letter country code (ISO 3166-1), like BR. The same codes as range.countriesWithOpenRecords, plus XK for Kosovo, the code GBIF uses. Each code has one row.
name
The everyday English name, like Brazil. Each name has one row.
continent
The continent, like South America. Islands far from any continent, such as Mauritius, have Seven seas (open ocean).
region
The United Nations region: Africa, Americas, Asia, Europe, Oceania or Antarctica.
subregion
The United Nations subregion, like Caribbean or Middle Africa.

The names follow Natural Earth, a free public-domain world map, exactly as it has them, and so do the continents and regions. Some read differently from other lists: CN is "People's Republic of China" and TW is "Taiwan".

Reading the CSV: Namibia's code is NA, which some tools read as a missing value. In pandas, pass keep_default_na=False to read_csv; in R, pass na.strings = character(0) to read.csv. DuckDB, the Parquet file and the JSON file keep it as the text NA.

Licenses

You may use critwire's data for anything, including school work and apps you sell, as long as you give credit (see Cite).

  • critwire's own data (records, ids, the country lists we work out) is CC BY 4.0: use it freely and credit "critwire". The full terms are in DATA-LICENSE.md.
  • Values from other sources keep their own license, recorded in each record's sources. All of them are open: CC0 or CC BY 4.0.
  • The countries files come from Natural Earth, which is in the public domain: no license and no credit needed, though critwire credits it anyway.
  • Photos keep their own license, in photo.license. Some need the same license on anything you make with them (the "SA" in CC BY-SA), so check before you reuse one.
  • Country lists are counted only from CC0 and CC BY 4.0 records on GBIF. The records themselves belong to the groups that shared them; they are listed under Credits.
  • IUCN: critwire stores only the Red List species id (ids.iucn) so you can match records. It holds no IUCN data. To use Red List data, get it from IUCN under their terms.
  • The code that builds these files is MIT licensed: LICENSE.

Cite

When you use critwire's data, credit it like this:

In a school report, a footnote or the sources list is enough. In an app, put it on an about or credits screen. If you show photos, show each photo's credit and license too. In research, also cite the sources you rely on: their citations are in Credits, and the GBIF DOI covers the country lists.
