# 001: critwire MVP (open species data at critwire.com, dogfooded by Critter Connect)

Moved from phaser-june `plans/049-critwire.md` on 2026-10-18; decisions are the owner's (grilling session 2026-10-18). Not started past step 0.

## What it is

A curated, open species database for people making nature apps for grades 6–12, Critter Connect first. PokeAPI-shaped (one clean record per animal), but published as data files you can query, not a query server.

- **Audience:** CC first (judges the MVP); docs and data public-quality from day one.
- **Scope:** curated records only, every one complete. Start with CC's 76 animals; add when CC or a user needs one. Not a GBIF/COL rival.
- **License:** content CC-BY 4.0, code MIT. Third-party fields and photos keep their own license in `sources[]`. No Wikipedia prose copied (share-alike); copy written fresh.
- **IUCN:** the crosswalk stores `sis_taxon_id` only (= shapefile `id_no`, = CC `iucnId`; never the assessment id). Users call IUCN with their own token. critwire never stores, caches, proxies or serves IUCN data (assessments, categories, ranges).

## Record

```json
{
  "id": 12,
  "slug": "blandings-turtle",
  "scientificName": "Emydoidea blandingii",
  "commonName": "Blanding's turtle",
  "taxonomy": { "class": "", "order": "", "family": "", "genus": "" },
  "ids": { "iucn": 0, "gbif": 0, "col": "", "wikidata": "", "inaturalist": 0, "ncbi": 0 },
  "range": { "countriesWithRecords": [] },
  "traits": {},
  "photo": { "url": "", "credit": "", "license": "", "page": "" },
  "sources": [
    { "source": "", "fields": ["ids.col", "taxonomy"], "license": "", "retrieved": "YYYY-MM-DD", "url": "" }
  ],
  "replacedBy": null
}
```

- **range:** no `realms` key until realms exist (not an empty array). `traits` is absent from `species.json` until traits are added.
- **sources[]:** one entry per source that filled a field; every third-party field (`ids.*`, `taxonomy`, `range.*`) in exactly one entry's `fields`. Entries carry the query URL and retrieval date, plus `doi`/`release` (COL) or `checklistKey` (GBIF backbone). `critwire base` covers `ids.iucn` and step-1 fallback taxonomy (no `retrieved`).

- **id:** critwire integer, never reused; slug is an alias (`/v1/species/12` = `/v1/species/blandings-turtle`). Outside keys are not stable enough to be ours (GBIF keys change on backbone rebuilds, COL ids on name revisions).
- **Splits/merges:** id stays with the record closest to the old concept; new species get new ids; a retired id returns `replacedBy: [ids]`.
- **Taxonomy:** COL via ChecklistBank API (CC-BY). GBIF used only for its key and occurrences.
- **Crosswalk:** one Wikidata SPARQL query (CC0: P627 IUCN, P846 GBIF, P10585 COL, P3151 iNat, P685 NCBI), checked against GBIF `species/match` and COL by name. Mismatches flagged for a person, never auto-fixed. `ids.gbif` is the legacy GBIF backbone key; `ids.col` is the stable COL id, also COL XR's key (GBIF's default taxonomy since June 2026).
- **Range (MVP):** countries from GBIF occurrence facets (filtered; "countries with records", not native range; owner overrides in `data/review/country-overrides.json`). Counted only from CC0 and CC BY 4.0 records; field is CC BY 4.0. GBIF aggregates have no DOI. Labelled critwire-derived, not IUCN. Realms later: GBIF points ∩ RESOLVE Ecoregions 2017 realms (CC BY 4.0), built with the polygons (Natural Earth has no biogeographic realms).
- **Traits:** single values from any source if cited and in our own words (facts, not prose); bulk imports only from open datasets (AVONET, AmphiBIO, EltonTraits, AnAge).
- **Photo:** Wikimedia Commons, per-file license, credit and page (as CC does now).

## Access

All static under `critwire.com/v1/`, written by each release:

- `species.parquet`, `ranges.parquet` (GeoParquet once polygons exist), `species.csv`, `species.json` (all), `species/{id|slug}.json`.
- DuckDB straight over HTTP: `SELECT * FROM 'https://critwire.com/v1/species.parquet'`. Same files open in QGIS, Excel, pandas.
- Static landing page + docs (Markdown to HTML, no framework): what it is, fields, licenses and credits, DuckDB quickstart.
- `/v1` shape is frozen; data updates go into `/v1` freely; a shape change ships as `/v2` with `/v1` kept.

## Build and ops

- **Source of truth: files in the repo.** `pnpm ingest gbif|col|wikidata` fetches and commits snapshots to `data/`; each data change shows up in a PR diff.
- **`pnpm build`:** load `data/` into Postgres (`critwire` db, rebuilt each time), run PostGIS/SQL steps, export `dist/` (DuckDB `postgres` extension writes Parquet), render docs.
- **Stack:** pnpm, TypeScript (`tsx`, postgres.js) + plain SQL. No web framework until the viewer.
- **Box:** Oracle VPS (`critter-vps`: ARM64, 2 cores, 11 GB RAM, ~24 GB free). Native Caddy serves critwire.com. VPS setup is done from the Oracle control room, never scripted from WSL.
- **Postgres 16 + PostGIS 3.4.2** (Hetzner has 17/3.5): no 3.5-only functions.
- **DBs:** `critwire` (live build) and `critwire_dev` (agents' scratch, never the live one). The old app's dev db became `critwire_feedback`; old `critwire_live` stays until cutover.
- **Paths:** agents' checkout `/srv/critter-ai/critwire` (old app's at `/srv/critter-ai/critwire-feedback`); live copy `/srv/apps/critwire`.
- **Workflow:** same GitHub hub as CC (`agent/<slug>` branches, PRs, owner merges). VPS agents push over HTTPS (`gh`).
- **Release:** the VPS's `deploy critwire` (owner's word only): pulls main into the live copy, `pnpm install --frozen-lockfile` + `pnpm build`, swaps `dist/` into what Caddy serves only if the build passed. Static, no server process. No CI or cron until there's a reason.
- **First deploy is the cutover** from the old Node app (back up `critwire_live`, stop `app@critwire`, Caddy -> static). Tell the owner before step 3 so it's scheduled, not accidental.
- **CORS on `/v1`:** `Access-Control-Allow-Origin: *`, allow `Range`, expose `Content-Range`, `Content-Length`, `Accept-Ranges`. Needed so DuckDB-WASM and other sites' browsers can read the files (DuckDB reads Parquet by byte ranges).

## Critter Connect side

- `npm run content -- build` fetches `critwire.com/v1/species.json` and copies taxonomy, ids and photos into CC's db. No runtime calls; critwire down never breaks play.
- CC keeps the game-only and IUCN-derived parts: clues, `redList`, IUCN realms/countries, `iucn` ranges (`clue_match_ranges`). It joins to critwire by id.
