# Mission: critwire's new look, the cw theme

This file is the mission's state. Agents: follow "In a mission session" in `~/.claude/CLAUDE.md`, and keep this file current.

## Brief


### Goal

Critwire's whole UI and brand move to the **cw** design language, which Danby made in Graphical (graphicalui.com, theme revision `bittw6orbj7l`), in light and dark.

1. **The guidance is installed in the repo.**
   - `GUI.md` and `gui/` are at the repo root, and the skills `graphical-ui`, `graphical-convert` and `graphical-audit` are under `.agents/skills/`.
   - `AGENTS.md` gains a short pointer, with nothing else in it replaced: "For UI work, follow GUI.md and use graphical-ui, graphical-convert, or graphical-audit as appropriate." The pointer also gives the skills' paths.
2. **cw is defined once, as named tokens, in critwire's existing theme system.**
   - The tokens cover cw's colours, neutrals, text steps, spacing, radii, borders, shadows, motion, focus and font roles, for both modes.
   - The theme system means the Tailwind v4 `@theme` in `globals.css`, the CSS variables of each surface, and Payload's admin variables.
   - Components use the named tokens. Literal values appear only in the token definitions.
3. **Critwire's own surfaces are fully converted, in light and dark:**
   - The home page `/`.
   - `signup`, `onboarding`, `verify`, `forgot-password`, `legal/*` (including `legal/accept`), `report-abuse` and the 404.
   - The share kit, and the shadcn `Button`.
4. **Critwire's brand is cw.**
   - The wordmark, the favicon (`.svg` and `.ico`), and the admin `Logo` and `Icon`.
   - A cw OG image, replacing the template's `public/website-template-OG.webp`. It's the default for any page without its own image (`src/utilities/generateMeta.ts`, `mergeOpenGraph.ts`).
   - The share kit's button images and live badge.
   - The auth and contact-form emails.
   - The old brand (`brand.css`: yellow `#f6d33c`, ink `#1d1f55`, the Anybody wordmark) is gone.
5. **The Payload admin is cw.**
   - Payload's own UI is themed through its theme variables (colours, font, radius) in both of its modes.
   - Critwire's custom admin views are fully converted: the sign-in, forgot and reset views, the dashboard (`BeforeDashboard`), the Issues kanban, the Share tab (with its Discord tab), and the legal gate.
6. **Studio portals and embeds sit on a cw base, in the studio's colours.**
   - cw's structure becomes the portal's: type scale, spacing, radii, flat surfaces, and the styling of every component, state and portal.
   - **cw dark becomes the default portal theme.**
   - Each studio's saved theme (colours, `typography`, `shape`, `density`, `motion`) still applies on top.
   - This covers `/g/<slug>` and all its pages, and the board, updates and floating-button embeds.
7. **Every component in scope has a status:** converted, already matches, intentionally preserved, or blocked, each with evidence or a reason. A `graphical-audit` pass has found and fixed the remaining gaps.

### Why

Danby is rebranding critwire around cw, so that the product, its admin and the base of every studio's portal look like one deliberately designed thing. Studios still own their colours. That's the white-label promise ("a hub in the studio's colours"), and it doesn't change.

### Scope

In:
- Installing the cw guidance (see Decision rules for the source).
- Styles, tokens, fonts, layout, components, states, motion and both modes on every surface listed in the Goal.
- The brand assets and emails listed in the Goal.
- Payload admin theming through `src/app/(payload)/custom.scss` and the SCSS of the custom views.
- Changing `DEFAULT_THEME_COLORS` and the defaults in `src/lib/game-portal/theme.ts`, and re-expressing the portal's `typography`, `shape`, `density` and `motion` tokens on cw's scales.
- Extending the screenshot harness (`playwright.screenshots.config.ts`, `tests/screenshots/`) with the views it doesn't cover yet: the admin sign-in, the Issues kanban and the legal gate, in light and dark.
- Updating the docs that describe fonts, colours, the default theme or the brand.

Out:
- New features, pages or routes, and changes to behaviour, data, handlers, accessible names, form values or keyboard interaction.
- Changes to stored studio themes. Every saved theme must stay valid without a migration.
- Weakening `siteThemeSchema`'s WCAG rules.
- Rewriting Payload's built-in components, ejecting its views, or replacing critwire's primitives with another library (Base UI, Radix).
- The embed loader's protocol and attributes, and its 5 KB budget (`public/embed/v1.js`, int test `embed-loader`).
- The text of the legal documents. UI copy changes only where a converted component needs it.
- Dependency versions, ranges, overrides and the lockfile. Add only a package the implementation truly needs, with `pnpm`, pinned the way `package.json` already pins.
- Merging and deploying. The live site runs `main`.

### Decision rules

- **The scope is already decided.** Danby chose "convert the whole app", with the exceptions in this brief, so don't ask GUI.md's "How would you like to apply this theme?" question. Follow `graphical-convert`:
  - Its "Map before editing" inventory and mapping is the Architecture stage: the `architect` writes it into the plan's Architecture section, and both reviews judge it against this brief and the theme.
  - Its "Verify and report" step, with `graphical-audit`, closes the mission.
- **Loading the skills.** Claude Code here doesn't discover `.agents/skills/`, so read `.agents/skills/<name>/SKILL.md` and its references directly, as GUI.md allows.
- **Where to install from.** Install from the ZIP staged at `/srv/critter-ai/agent-state/missions/cw-theme/source/bittw6orbj7l.zip`. It's the same revision as the registry item.
  - Use the published `https://www.graphicalui.com/r/bittw6orbj7l.zip` only if the staged file is missing.
  - Don't run `npx shadcn@latest add …`. It would break the repo's "never latest" rule, and it can touch `components.json`.
  - Copy `skills/*` to `.agents/skills/`.
  - Don't edit the downloaded reference files. Local decisions go in a "Local decisions" section that you add to `GUI.md`.
- **Accessibility wins over snapshot values.** Hold WCAG AA: 4.5:1 for text, and 3:1 for large text, field boundaries and focus indicators. Fix a failure with another cw token, never a new colour, and list it in the Summary. Known failures:
  - **The light primary button** is white (`neutral-1`) on `color-1` `#31c3e8`, which is 2.1:1. Use `neutral-10` on `color-1`; the theme's own `--cte-accent-text` is `#000000`.
  - **In light mode, `color-1`, `success`, `warning` and `error`** fail as text on the light neutrals. Use them as fills and marks with `neutral-10` text, never as body text, links, or the only edge of a control.
  - **Dark-mode edges disappear.** The snapshot's resolved edge is `rgb(0 0 0 / 0.1)` in dark mode too, `neutral-4-transparent` is close to invisible on `#000000`, and every cw shadow has opacity 0. Popups, fields and cards still need visible edges in dark mode. Use a cw neutral step that keeps them visible, and record it.
  - cw is flat by design. The 0-opacity shadows are intended; don't "fix" them.
- **Portals: cw is the base, and the studio's theme wins.**
  - `siteThemeSchema`'s contrast rules don't change.
  - The new `DEFAULT_THEME_COLORS` are cw dark: background `#000000`, foreground `#ffffff`, mutedForeground `#a1a3a6`, surface `#1f2022`, accent `#31c3e8`, accentForeground `#000000`, success `#76ef6b`, warning `#ffa344`, error `#ff5263`, and a border from the dark neutrals that stays visible. Check that they pass the schema.
  - cw light can't be a portal default: its accent on white is 2.1:1, under the schema's 3:1.
  - The default `typography` uses cw's font. The other choices keep their display voices (Archivo, Young Serif, Science Gothic, in `src/components/game/theme/fonts.ts`).
  - The Critter Connect demo theme and the screenshots' Riso theme keep their colours. They're the proof that white-labelling still works.
- **Fonts.** cw names "GT Standard M", a paid font. Danby chose a free look-alike instead, which is a deliberate substitution, not a silent one.
  - Pick the closest face that has a licence for commercial use (OFL or similar), weights 400, 500 and 700, and latin and latin-ext. Self-host it with `next/font`, with no runtime third-party requests.
  - Keep the family behind the cw font-role tokens (`--font-ui`, `--font-brand`, `--font-editorial`), so a licensed GT Standard can replace it in one place later.
  - The data role, "Sidebar Geist Mono", is Geist Mono (OFL), self-hosted the same way.
  - Record both choices in GUI.md's "Local decisions" and in the Summary.
  - Remove fonts that are no longer used (`src/fonts.ts`) only after checking that nothing uses them.
- **Icons.** cw names the "Central" icon set, which is paid. Keep `lucide-react` (already installed, and outlined), at cw's `--icon-stroke-width` of 2. Don't add an icon package.
- **The brand.**
  - The wordmark is "critwire" set in the brand font at its heavy weight, with cw's colours. No illustrated logo or mascot.
  - The favicon and the admin icon derive from the wordmark.
  - Keep the share kit's image URLs, sizes and formats stable. Studios have pasted them on their sites, and they're cached for a long time.
  - Emails stay email-safe: inline styles, the fallback font stack, and no web fonts required.
- **The admin.**
  - Use Payload's documented theme variables. Check their names against the installed `@payloadcms/ui` 3.85.2.
  - Keep Payload's light/dark/auto switch.
  - Avoid brittle selectors into Payload's internals beyond what the custom views need.
- **Modes.** Critwire's own pages follow the visitor's system setting (`prefers-color-scheme`), with no toggle. The embeds already do this, and the admin keeps Payload's switch.
- **When cw and a critwire requirement conflict** (accessibility, white-labelling, behaviour), the critwire requirement wins. Record it as "intentionally preserved", with the reason.
- **Order of work.** Do the guidance, the tokens and the shared components first. Then critwire's own surfaces and the brand, then the admin, then the portals and embeds, then the audit. If the 60-session limit is reached, whole surfaces are then done and the rest is listed.
- **Danby is asleep.** Anything that needs him goes in the handoff file. Pick the stronger option and carry on.

### Notes

- **Base:** this mission starts from `agent/legal-launch` (done, not merged), so the redesign covers its legal pages, signup boxes, form notices and legal gate.
- **The repo is public.** Committing `GUI.md`, `gui/` and `.agents/skills/` publishes them.
- **How styling works today:**
  - Tailwind v4 is set up in `src/app/(frontend)/globals.css` (with `@config tailwind.config.mjs`). shadcn supplies only `src/components/ui/button.tsx` (style "default", base slate). Everything else is hand-written CSS per surface:
    - `marketing.css`: critwire's site, on `.cw-root`.
    - `portal.css`: portals, on `.fs-root`, fed from the studio's theme by `src/components/game/theme/themeStyle.ts`.
    - `src/app/(embed)/embed.css`: already has light and dark.
    - `src/components/share/share-kit.css` and `src/components/marketing/brand.css`.
    - The admin's `src/app/(payload)/custom.scss`, `src/components/BeforeDashboard/index.scss`, `src/components/admin/share/index.scss` and `src/components/admin/issues/kanban.css`. Kanban compiles its own utilities.
  - Fonts: `src/fonts.ts` (Atkinson Hyperlegible Next for body text, Anybody for the wordmark) and `src/components/game/theme/fonts.ts` (the portal's display voices).
  - Theme code: `src/lib/game-portal/theme.ts`, `projectTheme.ts`, `src/lib/embed/theme.ts` and `src/collections/GameProjects/theme.ts`.
  - Share images: `src/lib/share/images.ts`. Emails: `src/lib/email/templates/`. Legal UI: `src/components/legal/`.
- **Versions:** Next 16.2.6, Payload 3.85.2, Tailwind 4.1, lucide-react 0.563.0.
- **The cw values:** `gui/themes/cw.md` has them for both modes, and `gui/themes/cw-components.md` (about 530 KB) has the effective assignment for every component, variant, part, state and mode. Read only the sections you need.
- **Screenshots:** `pnpm screenshots` needs `SHOTS_SET=before|after` and an absolute `SHOTS_DIR`. It drops the `_e2e` database like `pnpm test:e2e`, so never run the two together.
- **Accessibility floor:** the floor from `briefs/2026-09-29-design-pass.md` still applies: responsive down to 390 px, visible keyboard focus, `prefers-reduced-motion`, and contrast.
- **Ports:** keep port 3000 free. The previews (`hp-preview`, `critwire-demo`) are stopped while this runs.
