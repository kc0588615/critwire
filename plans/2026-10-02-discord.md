# Mission: critwire Discord

This file is the mission's state. Agents: follow "In a mission session" in `~/.claude/CLAUDE.md`, and keep this file current.

## Brief


### Goal

Players can send feedback from the studio's Discord server, and the server hears back when things change. All of it works through Discord's HTTP interactions, so there's no always-on bot process. When this mission is done:

1. **Feedback from Discord.** A critwire Discord app offers:
   - **`/feedback`:** opens a Discord form (a modal) that asks Bug or Idea, a title and details, plus platform and version for bugs. It creates a **private report in the game's review queue**, through the same content filter and the game's "review before public" setting (on by default). The player gets a private confirmation with a link to the board.
   - **"Send to critwire" on a message** (right-click → Apps): turns a player's Discord message into a report, credited to its author. Only members with Manage Messages can use it, so players can't import other people's messages.
   - **What a report records:** the Discord username and user ID, privately, so the studio can follow up. They're never shown publicly.
   - **Rate limits:** per Discord user, per game.
   - **Security:** every request's Ed25519 signature is verified, and old requests are rejected using the timestamp.
   - **No voting from Discord.** A Discord identity would be a second vote for the same person, which the owner rejected (2026-10-02).
2. **Posts to Discord.** Critwire posts to a channel the studio chooses when an update is published, and when a feedback item's **public stage** changes to Planned, In progress or Shipped.
   - Send one post per public stage change. Several changes in quick succession become one post.
   - Never post for flagged content, held games or suspended studios. The job loads data with `overrideAccess: true`, so it must check this itself.
   - Each post links to the item or the update on the portal.
3. **One setup.** The "Put critwire on your site" panel (from the `reach` mission) gets a **Discord** tab:
   - "Add critwire to your Discord" installs the app on the studio's server and links the server to the studio.
   - The studio picks the channel for posts. A webhook or the installed app may do the posting; the architect picks whichever needs fewer steps from the studio.
   - When a studio has several games, `/feedback` lets the player choose the game.
4. **Self-hosting.** The Discord features are off unless their environment variables are set. `docs/discord.md` explains, step by step, how a self-hoster creates their own Discord application and connects it.
5. **The hosted instance.** Add a handoff item with click-by-click steps for the owner: create critwire's Discord application in the Discord Developer Portal, copy the IDs and keys it needs, and, once production exists, set its Interactions Endpoint URL. This doesn't block the mission.

### Why

Indie studios' players talk on Discord. The tools indies adopt for feedback are Discord-first, and players won't go looking for a portal. The owner asked for feedback to be collected from Discord (2026-10-02). Posting status changes back closes the loop where the players are.

### Scope

In:
- Everything under Goal.
- Reuse what fits from the contact form's Discord webhook support: `isAllowedDiscordWebhookUrl` in `src/lib/validation/discordWebhook.ts` and the jobs queue. The review's Must-fix 5 explains why a new field and a new task are needed.

Out:
- A gateway bot that reads channels or forum posts.
- Voting from Discord, and syncing comments or threads.
- Other chat platforms.

### Definition of done

- `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm build` and the full E2E suite pass.
- New E2E tests send requests signed with a test key pair generated locally. Nothing calls the real Discord. They cover:
  - Rejecting a bad signature and an old timestamp.
  - `/feedback` creating a private report, with the content filter holding flagged text.
  - The permission check on the message command.
  - The rate limits.
  - Choosing the game when a studio has several.
  - Posts reaching the webhook sink, with one post per stage and quick changes combined.
  - No posts for held or suspended content.
  - The setup tab.
- Screenshots of the Discord tab, saved in `/srv/critter-ai/agent-state/missions/discord/screenshots/`.
- Branch `agent/discord` pushed. Don't merge it.

### Decision rules

- **No extra vote power.** Discord is an inbox, not a voting booth.
- **Private by default.** Discord reports go to the review queue like every other report, and Discord identities stay private.
- **Optional for self-hosters:** with no Discord settings, nothing changes.
- **Owner decisions go in the handoff file.** Pick the conservative option and carry on.

### Notes

- This mission builds on `agent/embed`.
- Discord sends interactions as HTTPS POST requests to one public endpoint, which must answer within 3 seconds. Use a deferred response for anything slower.
- The E2E webhook sink is at `tests/e2e/support/env.ts:18-20`.
- The review is at `/srv/critter-ai/agent-state/missions/briefs/2026-10-02-integrations-review.md`.
